Dynamics

Fitting during the process.

The point of this page

Everywhere else on this site is one fit examined after the fact. You run the experiment, then you analyse it. GRIN runs this fit with calibrated uncertainty in about a millisecond, whatever the trial count, which makes fitting cheap enough to do during data collection rather than after it. This opens up designs that a single after-the-fact fit doesn't typically allow: watching an estimate firm up trial by trial, catching drift while it's happening, stopping a session once you're confident in the fit rather than running a fixed number of trials.

Everything below is simulated and limits are flagged when and where appropriate.

Held constant across the run. Just note that we have found correlation to be a difficult parameter to pin down (see below), so to ensure our software looks as impressive as possible, we're only allowing you to play with separability because the fit tracks it more cleanly.

Separability sits at the above starting values until the 'intervention point' when it creeps toward the new (target) values via a Rescorla-Wagner-style approach (fast at first, slowing as it approaches the target).

Each layer is one checkpoint's fit; older ones fade as newer ones draw over them, the whole sequence is one picture of how the estimate moved, not just where it ended up. Each ellipse's orientation follows its recovered correlation, which carries wide uncertainty, so a tilt is not by itself evidence of a correlation (see An independence problem).

Early stopping

A fixed-N protocol runs every participant for the same number of trials regardless of how the data look. GRIN is fast and easy to fit and, more importantly for this use-case, returns uncertainty of it's estimates. This means that you can stop data collection the moment you're confident enough in the estimates, and skip the rest.
